Oxidtaxa — Full Visual Walkthrough

Companion to oxidtaxa_method.html. Where §10 of the method doc depicts a single query running through classification, this document expands that idea to the entire pipeline — training + classification — and depicts every qualitatively-distinct scenario on its own panel, all running against a single extended toy dataset. Every knob from TrainConfig and ClassifyConfig (except processors, which has no algorithmic effect) appears at its point of influence.

Reading this document

Each scenario is a single panel that answers three questions: what changes (the knob strip), what the model sees (intermediate numbers), and what comes out (the ClassificationResult). Scenarios are grouped by stage so the reader can skim by concern.

T1. K-mer enumeration & spaced seeds

Before anything else, each training sequence is reduced to its sorted set of unique k-mer IDs. At k=3 the universe is 4³ = 64 k-mers indexed AAA=1…TTT=64. Sliding a contiguous 3-window over seq1 = ACGTACGTAC gives {ACG, CGT, GTA, TAC}.

train k, seed_pattern, n

k (default auto): k-mer size. If k=None, oxidtaxa picks k = max(3, ceil(log4(n · L_avg / N_ref))) using the target n (default 500). seed_pattern (default None): binary mask selecting which positions within the window are read.

Scenario S16 — spaced seed collapses a SNP

S16 Spaced-seed k-mer collision

knobs: seed_pattern=11011 (weight=4, span=5)  vs  seed_pattern=None (contiguous k=4). The pattern's weight (number of 1s) is what oxidtaxa uses as k internally; span (pattern length) is the window size on the input.

Consider two near-identical sequences that differ only at position 3:

VariantSequenceContiguous 4-mersSpaced 4-mers under 11011
AACGTAACGT, CGTAAC_TA → read as ACTA
BACATAACAT, CATAAC_TA → read as ACTA

Effect. Contiguous k-mers give A and B disjoint k-mer sets → they look like different species to the classifier. The spaced seed masks position 3 (the SNP), collapsing both variants onto the same k-mer ID ACTA → they share the feature, and the classifier correctly lumps them into one genus. This is how spaced seeds buy robustness to point mutations without widening k.

T2. Per-rank IDF matrix

IDF is not a single vector — it's a matrix, one row per rank depth. The formula IDF_r(kmer) = ln(N_r / (1 + c_r)) uses the rank-specific count of distinct prefixes N_r and the rank-weighted occurrence count c_r. Per-rank c_r is normalized by group size so a 5-sequence genus doesn't dominate the kingdom-level row.

train per_rank_idf (always on)

Source: src/training.rs:741 (formula), src/classify.rs:689–693 (per-rank row lookup at descent depth).

Worked IDF matrix for the extended dataset

At k=3, against the 12-sequence training set, four of the 64 k-mers dominate the discrimination budget. Here's how each k-mer's IDF looks at each rank (numbers are illustrative — exact values depend on the per-rank group-size normalization):

Shown as ln(N_r) → actual ln(N_r/(1+c_r)). The rightmost column is what classify.rs:689–693 picks at each descent step.

Why a matrix, not a vector. A k-mer like ACG is noisy at kingdom (present everywhere) but discriminative at genus (only Canis has it on seq1/seq2/seq7/seq11). A single global vector would either over-weight it at kingdom or under-weight it at genus. The matrix lets the classifier pick the right row for the depth it's currently deciding.

T3. Feature selection at each decision node

At every internal node with at least two children, oxidtaxa picks a set of "decision k-mers" — the features that will be used at classify time to vote among the children. Three knobs change what gets picked.

train record_kmers_fraction, descendant_weighting, correlation_aware_features, max_children

record_kmers_fraction (0.10): fraction of n_kmers kept per node. descendant_weighting (Count): how child profiles are weighted when building the parent's q. correlation_aware_features (false): greedy de-dup using Bhattacharyya distance. max_children (200): above this the node is opaque.

Scenario S18 — correlation-aware selection de-duplicates

S18 Two highly-correlated top-entropy k-mers

knobs: correlation_aware_features = false (default) vs true

Suppose at a node two candidate k-mers have identical presence profiles across children: ACG and CGT, both present in every Canis sequence and absent elsewhere. Their information gain is the same.

Round-robin (false)
ACG CGT GTA GGC TAC

Both high-entropy k-mers selected. Redundant — ACG and CGT fire together so they each cast the "same" vote.

Correlation-aware (true)
ACG CGT GTA GGC TAC TTA

CGT's Bhattacharyya similarity to ACG is near 1.0 → penalty shrinks its effective gain to zero. Budget freed, TTA (Plantae-only) enters the kept list. The classifier now uses five independent signals instead of four-plus-a-duplicate.

How the metric works. Each candidate's per-child profile is L1-normalized (p̃ = p / Σp) and the sqrt is precomputed. Pairwise similarity is then BC(a, b) = Σ_j √(p̃_a(j) · p̃_b(j)) — a simple dot product. BC ∈ [0, 1], equals 1 for identical distributions, equals 0 for disjoint support. Bhattacharyya is well-defined for any split size, including n_children = 2 where Pearson correlation degenerates (any two 2D points have |r| = 1 by construction). The selection loop is entropy-descending with a per-candidate cached max_corr, allowing an early-exit optimization: once the entropy budget is exhausted, no remaining candidate can improve the gain. Total work O(R · C) where R = record_kmers and C = candidate pool size; parallelized when n_cand >= 2048. Source: src/training.rs:836–844 (Bhattacharyya rationale), src/training.rs:1119 (max_corr cache).

Scenario S19 — max_children makes a node opaque

S19 Hyper-branching node (real example: Bacillus, 18,011 species in 16S_Bacteria)

knob: max_children = 200 (canonical IDTAXA default; DECIPHER LearnTaxa(maxChildren=200))

This is a performance guardrail, not a truncation. At a node with N children, feature selection builds an N×n_kmers profile matrix; correlation-aware selection does O(N²) pairwise Bhattacharyya. With N≈18K (Bacillus) that's a ~300M-comparison step during training. IDTAXA (and oxidtaxa) skip feature selection entirely for such nodes. No DecisionNode is emitted.

Real-world frequency. Every production database we ship trips this: 16S_Bacteria has 154 opaque nodes (worst: Bacillus → 18,011 species); ITS1_Fungi 193; CO1_Metazoa 118; ITS2_Plants 96; even small amplicon DBs (12S, 16Smamm) have 1–2. So this path is exercised constantly on real data.

Normal node (≤ 200 children)
Opaque node (> 200)
Classify-time effect (correct)

dk.is_none() at classify.rs:222–227 → w_indices = (0..n_children) and break out of descent. Leaf phase still runs over every child subtree — species-level calls are still produced, just without Stage 1 bootstrap voting at this node. The degradation is in confidence quality (one giant 1-of-18K leaf-phase pick, not a chain of per-rank bootstraps) and in classify-time cost, not in path depth.

Practical consequence. On 16S/ITS/CO1 queries that route to Bacillus, Russula, or any other hyper-branching genus, the per-rank confidence curve flattens across the opaque node's rank and the species confidence reflects leaf-phase tot_hits/B over a huge candidate pool rather than a bootstrap vote share. Raising max_children above 200 recovers bootstrap voting at these nodes but blows up training cost (quadratic in correlation-aware mode). Lowering it makes more nodes opaque. 200 is IDTAXA's empirical sweet spot; oxidtaxa inherits the default.

T4. Fraction learning

After feature selection, every internal node starts with fraction[node] = max_fraction. Self-classification runs each training sequence through its own tree; if a node misclassifies a sequence, its fraction is nudged down by multiplier · |failures|/n_seqs. Nodes that hit min_fraction are masked (fraction=None) and effectively skipped at classify time.

train training_threshold, max_fraction, min_fraction, multiplier, max_iterations, use_idf_in_descent, leave_one_out

Defaults: 0.80 / 0.06 / 0.01 / 100.0 / 10 / false / false. The nudge-down block lives at src/training.rs:575–595.

Scenario S15 — leave_one_out reshapes the profile per k-mer

S15 Felidae (3 seqs) with per-kmer LOO active

knob: leave_one_out = true, fires for any group_size > 1 (singletons skipped)

For each training sequence, LOO subtracts that sequence's contribution from its matching sibling's raw k-mer counts and renormalizes by the reduced total. The shape of the profile changes (not just its scale) — singleton k-mers (only the held-out sequence has them) drop to zero; conserved k-mers (every group member has them) stay unchanged after renormalization.

For Felidae (n=3), held out is one of seq4 / seq5 / seq8. Its matching sibling is the Felis-Felis branch:

k-mer raw count (count of seqs with kmer) held-out has it? LOO-adjusted count LOO profile entry
GGC (3/3 conserved) 3 yes 3 − 1 = 2 2 / new_total ≈ 0.10 (≈ unchanged after renormalize)
CCG (2/3 partial) 2 no 2 − 0 = 2 2 / new_total ≈ 0.10 (slightly upweighted)
CGT (1/3 singleton; only seq8 has it) 1 yes (held out is seq8) 1 − 1 = 0 0.0 — k-mer drops out entirely

new_total = raw_totals[Felis] − |kmers[i]|. Singletons (the held-out sequence is the only contributor of CGT) go to zero — this is the bias correction working: at self-classification time, the held-out sequence's own unique k-mers no longer score it against itself. Conserved k-mers stay informative because the (count − 1) numerator and (total − |kmers[i]|) denominator scale together.

Why this matters. Earlier versions of the flag scaled all weights uniformly by (n−1)/n — but uniform scaling cancels in vector_sum's cur_weight / max_weight ratio, making the flag a no-op. Per-kmer LOO reshapes the profile (not just rescales it), so the bias correction is preserved through normalization. Source: src/training.rs:481–498, src/types.rs:280–289.

Singletons. A group of size 1 (e.g. Canis_aureus) skips LOO entirely: group_size > 1 is the gate. The size cap (previously "≤ 5") was removed in the bugfix — LOO now fires for any group with at least 2 members. The effect magnitude shrinks naturally with group size (a held-out 1 of 100 contributes less to the profile to begin with), so no upper cap is needed.

S7 Beam separates two children that both pass min_descend

knob: beam_width = 2 (defaults: min_descend=0.98, B=100)

When does beam diverge from greedy? Only when ≥ 2 children clear min_descend at the same split. The beam code at src/classify.rs:545 requires the top to pass; src/classify.rs:573–577 drops any runner-up that doesn't also pass — by design (in-source comment: "sub-threshold runner-ups are dropped … without algorithmic justification"). So 58/40 under default gate would halt for both beam and greedy.

The realistic case under defaults: tied bootstraps. The vote-counting loop at src/classify.rs:489–501 awards a vote to every child whose hits equal the rep's max, so ties inflate per-child counts beyond B. At Felidae → Genus, suppose q_beam_rescue's k-mers are nearly equally represented in the Felis and Lynx profiles. Most reps tie; final tally Felis 100, Lynx 98, miss 2 (totals exceed B because of ties).

Greedy (beam_width=1)
Beam (beam_width=2)

The real difference: greedy runs one leaf phase over the lumped {Felis ∪ Lynx} candidate pool at Felidae; beam runs two separately-contextualized leaf phases (each rooted at its own genus, with its own w_indices and descent margins). When the right genus is the runner-up, beam's per-genus context produces cleaner similarity scores. Source: src/classify.rs:545 (top-must-clear), src/classify.rs:573–577 (runner-up-must-also-clear), src/classify.rs:489–501 (tied-rep voting).

Footnote: the same divergence can occur without ties if the user lowers min_descend (e.g., to 0.40) — then a clean 55/45 split puts both children over the gate. Either way, beam's distinguishing trait is "≥ 2 children pass," not "rescue the runner-up."

S11 length_normalize dampens a long reference

knob: length_normalize = true

Long references have more unique k-mers, so they score more raw hits for the same query overlap. Normalization divides each reference's contribution by sqrt(n_unique/avg).

Referencen_uniqueRaw hitssqrt(n/avg) divisorNormalized hits
seq1 (Canis_lupus, short)430√(4/5.5) = 0.8530/0.85 = 35.3
seq10 (Vulpes_vulpes, long)1028√(10/5.5) = 1.3528/1.35 = 20.8

Without normalization, seq10 (28) is close enough to seq1 (30) to tie. With normalization, seq1 reaches 35 vs seq10's 21 — the long reference is demoted out of the false tie, and Canis wins decisively. Note on avg: the divisor is computed against the keep-local mean of the candidate pool at the leaf-phase stop node — not a global per-database constant. Two queries that route to different leaf-parent nodes will see different averages, even on the same reference. At single-keep (one ref in the candidate pool) avg = n_unique and the divisor is 1.0 → the flag is structurally inert (the singleton-leaf gotcha case). Source: src/classify.rs:801–816.

Stage 1 (per-replicate share-split filter). When the tied set contains both Canis (ancestor) and Canis_lupus (descendant), Canis is dropped from the tied set before share-split. share = 1 / 1 = 1.0 goes entirely to Canis_lupus. Stage 2 (post-bootstrap winner-stage filter). Belt-and-suspenders for cases where prefix-related groups land at equal tot_hits from disjoint-replicate wins. In our byte-identical case, Stage 1 already zeroed the ancestor, so Stage 2 has nothing to do — but on real data the ancestor often has some outright-win replicates (replicates where it strictly beats the descendant on its own evidence). Those still count; only the tied credit is suppressed.

S13 below_threshold truncates the reported prefix

knobs: threshold = 60, rank_thresholds = None

After roll-up, confidences are monotonically non-decreasing toward Root. If the species rank falls below threshold but the kingdom is confident, the taxon is truncated at the first rank that fails.
